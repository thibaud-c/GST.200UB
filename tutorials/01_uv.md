# 1. Manage the course environment with uv

[Tutorial index](README.md) · Next: [VS Code](02_vscode.md)

## Cheatsheet

Run these in your separate terminal, from the course root unless noted otherwise.

| Command | Use |
| --- | --- |
| `uv sync` | Install or update the project's environment |
| `uv add rich` | Add a package to the project |
| `uv remove rich` | Remove that package requirement |
| `uv run python practice/hello.py` | Run an ordinary Python file |
| `uv python install 3.14` | Install a Python version |
| `uv python pin 3.14` | Select a compatible Python version for the project |
| `uv run python --version` | Check the Python version the project uses |

`rich` is an example package. Practise adding and removing it in the separate project at the end of this guide.

Allow about 25 to 35 minutes, plus downloads. First follow the [course cloning steps](../README.md#clone-the-course-repository). You need your clone and a separate PowerShell or Terminal window. No Python installation is required before installing uv. If `cd` or `ls` is unfamiliar, see [terminal navigation, section 2](03_cli.md#2-look-before-you-move).

## 1. Install uv

uv installs Python and the packages a project needs. A project's **environment** contains its Python interpreter and installed packages. Keeping a separate environment for each project lets them use different package versions. Use the command for your operating system from [Astral's installation guide](https://docs.astral.sh/uv/getting-started/installation/).

**Windows PowerShell:**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**macOS/Linux:**

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

These commands download and run Astral's installer. The PowerShell policy option applies to that new process. On a managed computer, use your institution's installation procedure if scripts are blocked.

Close and reopen the terminal, then check:

```sh
uv --version
```

Expect a version number. Restart VS Code too if it was already open, so its extensions can find uv. The shell finds programs through `PATH`, a list of folders to search; a newly opened application picks up installation changes.

> [!TIP]
> If PowerShell says `uv` is not recognised just after installation, close and reopen PowerShell. To keep using the same session, add the installer's default folder to its search path:
>
> ```powershell
> $env:Path = "$HOME\.local\bin;$env:Path"
> uv --version
> ```
>
> This changes `PATH` for the current session only. `$HOME` is your user folder. If the installer reported a different location, use that folder instead. If `uv` is still missing, check whether the installer finished successfully.

## 2. Install the course packages

Enter your clone. If you used the README's location:

```sh
cd ~/university/GST.200UB
ls
uv sync
```

`ls` should show `pyproject.toml` and `uv.lock`. `uv sync` creates or updates `.venv`, the local Python environment. It can download a suitable Python interpreter when needed.

| Item | What it contains |
| --- | --- |
| `pyproject.toml` | The required Python version and package requirements |
| `uv.lock` | The resolved package versions |
| `.venv/` | The installed environment on this computer |

A **package** supplies reusable Python code. A **dependency** is a package this project needs. The course includes marimo with SQL support, DuckDB, and geospatial packages. The current Python requirement is `3.14.*`.

Open `pyproject.toml` as a file in VS Code's Explorer to read the `requires-python` line and package list. `.toml` is a format for configuration text. The filename is not a terminal command. See [opening the folder, VS Code section 2](02_vscode.md#2-open-the-course-folder).

> [!IMPORTANT]
> Run `uv sync` after `git pull` to pick up changed package requirements. Do not run `uv init` inside this existing course project.

Check the result:

```sh
uv run python --version
uv run python -c "import marimo; import duckdb; print('Course imports work')"
```

Expect Python 3.14 and `Course imports work`. The `-c` option runs a short piece of Python written inside quotes. `import` loads a package.

## 3. Use the environment in VS Code

After syncing, follow the next tutorial to [install VS Code](02_vscode.md#1-install-the-editor), [open the course folder](02_vscode.md#2-open-the-course-folder), and install the [Python and marimo extensions](02_vscode.md#5-install-python-and-marimo-support). You can return here for the environment-selection steps.

Open the Command Palette with **Cmd+Shift+P** on macOS or **Ctrl+Shift+P** on Windows/Linux. Choose **Python: Select Interpreter** and select the course `.venv`. When a marimo notebook asks for a kernel, select that same environment.

If `.venv` is missing from the list, choose **Enter interpreter path > Find…** and select the interpreter inside your course clone: `.venv\Scripts\python.exe` on Windows or `.venv/bin/python` on macOS/Linux. Then reopen the notebook and select this environment as its kernel. See the [VS Code fallback steps](02_vscode.md#5-install-python-and-marimo-support) if the kernel picker still does not show it.

Open an existing notebook with **marimo: Open as marimo notebook**. The [marimo tutorial](05_marimo.md) explains creating and running cells. There is no notebook launch command to keep running in your terminal.

> [!TIP]
> If an import works with `uv run` but fails in a notebook, the notebook may be using another environment. Select the course `.venv` and use **marimo: Restart notebook kernel**.

## 4. Add and remove packages

For a project you maintain, adding a package is one command:

```sh
uv add rich
```

This installs the package and updates both `pyproject.toml` and `uv.lock`. Removing the requirement uses:

```sh
uv remove rich
```

uv removes it from the environment if nothing else requires it. See [managing dependencies](https://docs.astral.sh/uv/concepts/projects/dependencies/).

For the course clone, add a package when a lab or the instructor asks for it. Keep `pyproject.toml` and `uv.lock` together when recording a dependency change in Git. Use the separate exercise project below to experiment freely.

## 5. Run an ordinary Python file

A script is a text file of instructions executed from top to bottom. To try one, create `practice/hello.py` in VS Code and save it, following [VS Code section 4](02_vscode.md#4-create-a-file-and-preview-it):

```python
print("Hello from GST200B")
```

From the course root in your separate terminal:

```sh
uv run python practice/hello.py
```

Expect `Hello from GST200B`. `uv run` chooses the project environment, so you do not need to activate `.venv` manually. The [Python tutorial](06_python.md) teaches the language inside a marimo notebook in VS Code.

## 6. Install or change Python

Installing an interpreter and choosing it for a project are different steps:

```sh
uv python install 3.14
uv python pin 3.14
uv sync
uv run python --version
```

`install` downloads Python. `pin` writes the preferred version to `.python-version`. `sync` brings the environment into line with the project. A pin can select only a version compatible with `requires-python` in `pyproject.toml`. See [installing Python](https://docs.astral.sh/uv/guides/install-python/) and [Python versions](https://docs.astral.sh/uv/concepts/python-versions/).

`.python-version` is also a text file, not a command. Open it in VS Code's Explorer or read it from the project folder:

**Windows PowerShell:**

```powershell
Get-Content .python-version -Encoding UTF8
```

**macOS/Linux:**

```sh
cat .python-version
```

Expect `3.14` after the pin above. Open `pyproject.toml` in the editor too: `.python-version` selects a preferred interpreter, while `requires-python` states which versions the project allows.

Keep Python 3.14 for this course. If you maintain a different project and want to move from 3.13 to 3.14, check package compatibility, edit that project's `requires-python` if necessary, then install, pin, sync, and rerun its code. Pinning alone does not change which Python versions the project allows.

After switching versions, reselect the environment in VS Code and restart notebook kernels. Do not try to change the environment while those kernels are running.

## If a command fails

| Symptom | Next step |
| --- | --- |
| `uv` is not found | Reopen the terminal; on Windows, try the session `PATH` fix in section 1 and check `uv --version` |
| `.venv` is missing from the notebook kernel picker | Select its interpreter by path, then reopen the notebook; see section 3 |
| No `pyproject.toml` found | Run `pwd` and navigate to the course root |
| Requested Python is incompatible | Check `requires-python`; the course currently requires 3.14 |
| A package download fails | Check your connection or institution's proxy; keep the error message |
| A package cannot be built or installed | Record the package, OS, Python version, and uv version for help |
| Notebook import fails after adding a package | Check its selected environment and restart its kernel |
| `VIRTUAL_ENV` does not match the project environment | When switching projects, this warning is expected; see the note below |

> [!NOTE]
> A `VIRTUAL_ENV` mismatch warning can appear when your shell still points to another project's activated environment. For the `uv sync` and `uv run` commands in this guide, uv uses the current project's own `.venv` by default. The warning alone is not a failed installation. Check your location with `pwd` and continue if you are in the intended project. A fresh PowerShell or Terminal window avoids carrying that activation into the next project. See [uv's project-environment explanation](https://docs.astral.sh/uv/concepts/projects/config/#project-environment-path).

## Exercise: manage a small project

1. In your separate terminal, create a project outside the course clone (see [section 2](#2-install-the-course-packages), [navigation, CLI section 2](03_cli.md#2-look-before-you-move), and [creating folders, CLI section 4](03_cli.md#4-create-and-enter-a-folder)):

   ```sh
   cd ~/university
   mkdir uv-practice
   cd uv-practice
   uv init --python 3.14
   uv sync
   ```

   Use another folder name if `uv-practice` already contains work. Here `uv init` is appropriate because this is a new project.

2. Run `uv add rich`. Open this practice folder in VS Code, then click `pyproject.toml` in Explorer and find the new requirement (see [section 4](#4-add-and-remove-packages) and [VS Code section 2](02_vscode.md#2-open-the-course-folder)).
3. Create `hello.py` containing `print("My practice environment works")`, save, and run `uv run python hello.py` (see [section 5](#5-run-an-ordinary-python-file) and [creating a file, VS Code section 4](02_vscode.md#4-create-a-file-and-preview-it)).
4. Run `uv remove rich`, then reopen `pyproject.toml` in the editor and check the package list (see [section 4](#4-add-and-remove-packages)).
5. Run `uv python pin 3.14`. Read the file with `Get-Content .python-version -Encoding UTF8` in PowerShell or `cat .python-version` on macOS/Linux. Confirm the selected version with `uv run python --version` (see [section 6](#6-install-or-change-python)).
6. Explain what `sync`, `add`, and `run` each changed. Why should you share the project files rather than copying `.venv` to a classmate (see [section 2](#2-install-the-course-packages), [section 4](#4-add-and-remove-packages), and [section 5](#5-run-an-ordinary-python-file))?

You are done when the script runs and you can identify which file records package requirements and which records the Python preference. Return to the course folder before continuing.
